Product scope · codename silo

Silo is the base. The mind sits on top.

A self-owned store you feed web material into — captured with real metadata, structured cleanly, and served to you and to an agent over MCP. Silo holds no AI itself; its whole job is to be the best possible answerable base for an intelligence (Claude) that searches it, traces your activity, and surfaces patterns from outside. Successor to the archived harbor.

The binding principle

No AI lives inside silo.

Silo captures, structures, and serves. Every intelligent act — semantic search, trend-tracking, pattern-spotting, summarizing — is performed by an external agent reaching in over MCP. Silo's obligation is only to hold the data in a form that answers well.

The spine — what the first build nails

One motion, done well enough to trust. Everything else is a stub until this is solid.

  1. Save a link — paste one (or a few) into silo
  2. Silo prepares its metadata — fetches title, description, site, image, and full text; the entry arrives understood and answerable
  3. It lands as a rich entry in a list you trust — scannable, not a wall of blue links
  4. Tags organize it — the one lightweight primitive (they also carry any "toread/done" workflow, so no separate queue)
  5. Find it again — basic full-text search across everything saved (capture is only worth it if find-later works)
  6. Import a pile in, export it all out — never locked in, from day one

Captured richly and structured cleanly from the first save — so the agent layer bolts on later without a re-capture.

What silo is deliberately not

The anti-scope is a feature — and the top two lines are what give silo its identity. Harbor bloated because it refused to say no; these are the no's that keep silo small and sharp.

  • No AI inside silo. Silo never summarizes, classifies, or "understands" on its own. All intelligence is an external agent over MCP. Silo is the shelves, not the librarian.
  • Not a file store. Silo saves references to web material — no PDF/document upload, no ingesting local files. If you can't point a URL at it, it's not silo's job.
  • Not a content archive. No permanent page snapshots (harbor's SingleFile). Silo stores metadata + extracted text, not a frozen copy of the page. Deletion is soft (trash → auto-purge), not hoarding.
  • Not trying to natively understand every website. "Just a link" is the floor; source plugins are the opt-in upgrade for the few sources you care about.
  • Not harbor's everything-store. No restaurants / products / apps as first-class types, no 8-intent taxonomy, no weekly digest, no read-later queue (tags do that job).
  • Not multi-user. Silo is single-user and private — yours. No sharing, no accounts-for-others, no social layer.
  • Not deciding its stack yet. Every technical/infra choice is intentionally open — product shape comes first.
